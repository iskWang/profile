# Project guide

This is the shared project guide. Root `AGENTS.md` and `CLAUDE.md` are regular text files pointing here; keep project instructions in this file.

## Quick paths & commands

- Blog posts: `content/blog/<kebab-slug>.{zh,en}.md` (images under `public/blog/assets/<kebab-slug>/`)
- Writing style (local-only): `.agent/personal-writing-style.md`
- Resume sources: `content/resume.{zh,en}.md` → `bun scripts/resume-content.mjs` (updates `src/generated/content.js`, `public/resume.{zh,en}.md`, `public/llms.txt`)
- Fast blog validation: `bun scripts/validate-blog-content.mjs`
- Full tests & build: `bun test` and `bun run build`

## Architecture

- The portfolio and bilingual blog use Astro static pages with React components. Add client hydration only where browser interaction requires it.
- Locale routes live in `src/pages/zh-tw/` and `src/pages/en/`. Content uses `zh` / `en`; the Chinese URL prefix is `zh-tw`.
- `src/layouts/Layout.astro` owns the HTML shell and theme scripts; `ArticleLayout.astro` owns article rendering. Homepage sections remain in `src/sections/`.
- `src/components/Header/Header.jsx` is shared by home and blog pages. Preserve the requested navigation order: About → Blog → Projects → Skills → Experience → Contact.
- Hosting uses Cloudflare Workers Static Assets. `src/worker.js` handles HTTP routing around the generated assets; consult `wrangler.json` for deployment configuration.

## Content changes

- Edit resume content in `content/resume.zh.md` and `content/resume.en.md`, then run `bun scripts/resume-content.mjs` (or `bun run generate-resume-content`). The generator owns `src/generated/content.js`, public Markdown resumes, and `public/llms.txt`.
- For blog copyediting or tone rewrites on existing posts (`content/blog/<slug>.{zh,en}.md`), read `.agent/personal-writing-style.md` first; keep `summary` ≤ 200 characters, preserve frontmatter/wikilinks, and sync `.zh.md` and `.en.md` (`translation: machine-assisted` stays on `.en.md` only). Skip scanning unrelated posts or reading schema files unless needed.
- For new blog posts, new markup patterns, or schema/validation changes, also read `content/blog/_TEMPLATE.md`, `src/content.config.ts`, and `scripts/blog-content-rules.mjs`.
- For blog post images, store assets under `public/blog/assets/<kebab-slug>/`, preserve original source photos (e.g., `.jpg` / `.png`) in that directory, and reference resized `.webp` derivatives in article Markdown/HTML. Size `.webp` images to fit the rendered container at ~2x display density (e.g., `720×960` for 3:4 `.post-ig-card` carousel slides at `19.5rem` / `312px` width; `~700px` max width for `22rem` `.post-figure--portrait`; `~1344px` max width for `42rem` standard `.post-figure`), and set matching `width` and `height` attributes on `<img>`.
- When writing or rewriting blog posts, stay within the repository and the target article unless the user explicitly asks to import from an external path (never proactively scan `~/.omp`, local dotfiles, or local Obsidian vaults, and never expose private project names or local machine details).
- Keep drafts out of pages, lists, feeds, related posts, and sitemap output. Match links and recommendations to the current language.
- `ASTRO_MIGRATION_PLAN.md` records the migration rationale and historical requirements; verify implementation details against current code and newer user decisions.

## Visual conventions

- Reuse the paper, ink, and teal theme tokens in `src/index.css` and their Tailwind mappings. Use utilities for layout and shared CSS for complex styling.
- Article pages prioritize quiet reading, clear typography, and restrained framing. Preserve mobile readability and both light and dark themes.
- Keep shared navigation and outer blog container widths consistent across list and article pages.
- Follow existing React component folders and their `index.js` exports; use Astro pages/layouts for document structure.

## Verification and release

- Use Bun; `package.json` and `bun.lock` define commands and dependencies.
- For iterative blog body edits (no frontmatter `title`/`summary` or code changes), run `bun scripts/validate-blog-content.mjs` instead of rebuilding the full site on every draft pass.
- After functional changes, frontmatter `title`/`summary` updates, or before final commit/push, run relevant `bun test` tests and `bun run build`. The build regenerates resume/llms content and validates blog content before compiling Astro pages.
- For release verification, inspect `dist/sitemap.xml` generated by `bun run build`. Verify all new public pages and blog posts are present, blog entries have `<lastmod>` derived from frontmatter (`updated` or `date`), drafts remain excluded, and any non-Astro standalone paths (like `/slides`) are registered under `customPages` in `astro.config.mjs`. Confirm external links and robots.txt point to canonical `/sitemap.xml`.
- For UI changes, verify affected pages at mobile and desktop widths. For Worker routing changes, verify HTTP behavior with a local Workers runtime: Astro dev/preview does not execute `src/worker.js`.
- Review `.github/workflows/` when changing release behavior. A merge/push to `main` triggers the production deployment workflow; an uploaded preview version does not switch production traffic.
- Deploy only when the user explicitly authorizes it. Keep local validation separate from `bun run deploy` / `wrangler deploy`.

## Pull requests

- Open PRs as the agent account (`iskwang-agent`); never as the repository owner. Commit author and committer must be the agent account.
- PRs are squash-merged with the PR body as the commit message, so the PR body is the permanent record. Use a conventional-commit PR title.
- After the last push (a rebase or author rewrite changes hashes), add a `Commits:` list to the PR body: one `- <short hash> <subject>` line per branch commit. The hashes disappear from `main` on squash; `git fetch origin pull/<N>/head` recovers them while GitHub keeps the PR ref.
- Before pushing, get a PASS from an independent reviewer on `git diff main...HEAD`; send fixes back to the same reviewer. The human merges.
