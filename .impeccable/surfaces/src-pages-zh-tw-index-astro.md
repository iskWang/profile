## Direction contract

THESIS: The site is Josh's 驗收單 (delivery acceptance record): every claim is a row with context, action, result and a dated "已交付" seal. Refuses the dark dev-portfolio hero + skill-badge grid.

OWN-WORLD: Paper form stock, ruled table grid in ink hairlines, document number + page count in the header, monospace form numerals. One seal red reserved exclusively for Josh's own delivery seals (never company seals, never decoration). Teal retires. State by shape: round seal = delivered, square seal = in progress (PickleScout / current role). Light and dark themes both kept (dark = carbon-copy blue-black stock).

STORY: Visitor sees a signed record, scans outcomes first, drills into each numbered item (addressable URL `#item-01`), then reaches the 簽核 block to contact.

FIRST VIEWPORT: Form header (document no. JW-2026, page 1/N, name, one-line role), then an outcomes table of 3–4 rows (項次 / 需求 / 結果 / 狀態 seal). Sign-off strip at bottom: Josh's name seal + primary action 聯絡 + resume PDF.

FORM: Acceptance form. Experience = itemized 驗收項目 per role with 條件 → 做法 → 結果 rows; skills = 使用器材 inventory list; blog = 技術附件 (appendices, numbered 附件 A/B/C); article = attachment document with form header and plain reading column.

SIGNATURE: Seal press — on first view each delivered row's seal stamps once (scale + ink settle, ~250ms, staggered), static under reduced motion. Legend explaining seal shapes held fixed in the form header.
